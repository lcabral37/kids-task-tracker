## 🎯 How It Works

**Architecture**: Local-First with Optional Backend
1. App uses localStorage for offline operation
2. Backend is optional - data syncs when available
3. Bulk upsert strategy prevents conflicts
4. PIN protection for child accounts

**Data Flow**:
Frontend (Zustand) ↔ localStorage ↔ API ↔ Backend (SQLite)

## 🚀 Getting Started

**Start Backend Server**:
```bash
cd /development/kids-task-tracker/server
npm run dev
```

Server listens on http://localhost:3001

**Test API**:
```bash

```

**Build Frontend**:
```bash

```
